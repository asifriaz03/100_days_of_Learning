## Topic: Ports & Common Port Numbers

### What I Learned

Today's focus was networking ports: what they are, how they're categorized, and the common port numbers every security professional needs to know by memory.

#### 1. What a Port Actually Is

A port is a 16-bit number (0 to 65535) used alongside an IP address to identify a specific process or service running on a machine. If an IP address is like a building's street address, a port is like the specific apartment or office number inside it, it tells traffic exactly which application should receive it. Every network connection is defined by a combination of source IP, source port, destination IP, destination port, and protocol (this combination is called a socket).

#### 2. Port Ranges

Ports are split into three official ranges:
- **Well-Known Ports (0 to 1023)**: reserved for standard, widely used services (HTTP, FTP, SSH, DNS, etc.), usually require admin/root privileges to bind to
- **Registered Ports (1024 to 49151)**: assigned to specific applications by IANA but not as strictly controlled (e.g. MySQL on 3306)
- **Dynamic/Private Ports (49152 to 65535)**: also called ephemeral ports, used temporarily by client applications for outgoing connections, assigned automatically by the OS

#### 4. TCP vs UDP Ports

The same port number can technically be used by both TCP and UDP independently since they're separate protocols:
- **TCP**: connection-oriented, reliable, used where data integrity matters (web, file transfer, email)
- **UDP**: connectionless, faster but unreliable, used where speed matters more than guaranteed delivery (DNS lookups, streaming, VoIP)

#### 5. Port States (from a scanning perspective)

When scanning a target (e.g. with Nmap), a port shows up in one of a few states:
- **Open**: a service is actively listening and responding
- **Closed**: the port is reachable but nothing is listening on it
- **Filtered**: a firewall is blocking traffic to the port, so it's unclear whether anything is listening
- **Unfiltered**: reachable, but state can't be determined without further probing

#### 6. Why This Matters for Security Work

- **Attack surface mapping**: every open port is a potential entry point, recon almost always starts with a port scan to see what's exposed
- **Service fingerprinting**: knowing standard port-to-service mappings lets you quickly guess what's running on a host, and spot anomalies (e.g. SSH running on a non-standard port can indicate evasion, or a service on an unexpected port can indicate malware/backdoors)
- **Firewall and hardening decisions**: defenders close unused ports and restrict access to necessary ones as a core hardening step, this is the practical side of "reducing attack surface"
- **Connects directly to previous days**: this ties Day 2's Wireshark work together, filters like `tcp.port == 443` only make sense once you actually understand what's happening on that port and why

### Key Takeaways
- Ports are how a single IP address serves multiple services at once, the IP gets you to the machine, the port gets you to the right application
- Memorizing the well-known ports (especially 20/21, 22, 23, 25, 53, 80, 443, 445, 3389) is non-negotiable for both offensive recon and defensive monitoring
- Port state (open/closed/filtered) is often more revealing during a scan than the port number itself

### Problems Faced
- Some ports serve multiple possible services depending on context (e.g. 8080 can be a proxy, an alternate web server, or something custom), so port number alone isn't always enough, banner grabbing and further enumeration are often needed to confirm what's really running
