### What I Learned

Spent over 5 hours today going deep into **Wazuh**, a free and open-source SIEM/XDR platform, working hands-on with the real-time monitoring interface rather than just reading documentation. This was one of the most hands-on, high-yield days so far.

#### 1. What Wazuh Actually Is

Wazuh is an open-source security platform that combines:
- **SIEM** (Security Information and Event Management): collecting, correlating, and alerting on logs from many sources
- **XDR** (Extended Detection and Response): extending visibility across endpoints, cloud, and network layers
- **HIDS** (Host-based Intrusion Detection): its original core, based on OSSEC

It's essentially the centralized "brain" that ingests logs from agents installed on multiple machines and turns raw data into actionable alerts.

#### 2. Architecture: Manager, Agents & Dashboard

- **Wazuh Manager**: the central server that receives data, applies detection rules, and generates alerts
- **Wazuh Agents**: lightweight software installed on endpoints (Windows, Linux, etc.) that forward logs, file integrity data, and system info to the Manager
- **Wazuh Indexer** (built on OpenSearch): stores and indexes all the processed data
- **Wazuh Dashboard**: the real-time web interface used to search, visualize, and investigate alerts

Understanding this pipeline (Agent to Manager to Indexer to Dashboard) made it clear how a single event on an endpoint eventually becomes a visible alert.

#### 3. The Real-Time Dashboard

Spent most of the session inside the live dashboard, exploring:
- **Security Events**: real-time feed of alerts as they're generated, filterable by severity, agent, or rule
- **Agent status**: checking which endpoints are active, disconnected, or reporting
- **MITRE ATT&CK integration**: Wazuh maps many detections directly to MITRE ATT&CK tactics/techniques, which connects raw alerts to actual adversary behavior categories
- **Vulnerability Detection module**: scans installed software on agents and flags known CVEs
- **File Integrity Monitoring (FIM)**: tracks changes to critical files/directories in real time, useful for spotting unauthorized modifications or persistence attempts

#### 4. Rules and Alert Severity

Learned that every alert is tied to a **rule ID** and a **severity level (0 to 15)**, similar in spirit to Windows Event IDs but built specifically for correlation. Higher-severity rules (e.g. brute-force detection, rootkit indicators) surface more prominently, and rules can be customized or written from scratch to fit specific environments. This is where Wazuh becomes genuinely powerful rather than just a log viewer.

#### 5. Log Sources Feeding Into Wazuh

Connected the dots between this and previous days: Wazuh doesn't generate its own raw data, it ingests and correlates:
- Windows Event Logs (Security, System, Application, tied directly to Day 1's topic)
- Syslog from Linux systems
- Firewall/IDS logs
- Application-specific logs

This made clear why understanding raw logs first (Day 1) and raw traffic first (Day 2) matters. Wazuh sits on top of both and turns them into correlated, actionable alerts.

#### 6. Why This Matters for Security Work

- Wazuh is a realistic, free alternative to enterprise SIEMs like Splunk or Microsoft Sentinel, excellent for building a home lab that mirrors real SOC work
- Real-time monitoring is the practical bridge between "knowing what an attack looks like" and "actually catching it as it happens"
- The MITRE ATT&CK mapping is a genuinely valuable skill: being able to say "this alert maps to T1110 Brute Force" speaks the same language SOC teams and job interviews expect
